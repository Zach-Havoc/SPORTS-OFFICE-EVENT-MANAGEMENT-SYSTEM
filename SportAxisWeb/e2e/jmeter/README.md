# Apache JMeter load test

Measures response times, throughput and error rate of the API while many
users use it at once. It runs only against the local throwaway copy (database
`sportaxis_e2e`, API on :8001), never the dev database or production.

## Install (once, no sudo)

```bash
T=~/.local/share/sportaxis-tools && mkdir -p $T && cd $T
curl -L https://archive.apache.org/dist/jmeter/binaries/apache-jmeter-5.6.3.tgz | tar xz
mkdir jre && curl -L "https://api.adoptium.net/v3/binary/latest/21/ga/linux/x64/jre/hotspot/normal/eclipse" | tar xz -C jre --strip-components=1
```

Elsewhere, set `JMETER_HOME` and `JMETER_JAVA_HOME`.

## Run

```bash
cd SportAxisWeb
npm run test:load
```

`run.sh` builds the throwaway site and starts the API (with as many PHP
workers as CPU cores and the rate limits lifted, so the test measures the
server, not the limiter). `run-jmeter.mjs` then creates temporary accounts,
a game with a committee member and a training session, and runs:

| Thread group | Requests |
|---|---|
| Public schedule and standings | `GET /api/events`, `/api/leaderboard`, `/api/live-scores` |
| Login authentication | `POST /api/login` |
| Attendance submission | `POST /api/attendance/sessions/{id}/records` (coach) |
| Score processing | `POST /api/scores` (committee) |
| Ranking computation | `GET /api/rankings/{event}`, `/api/leaderboard` |
| Report generation | `GET /api/reports/events/{event}`, standings CSV (admin) |

Each group runs for 45 s at each level of 10, 25, 50 and 100 concurrent
users (10 s ramp-up, 0.5–1.5 s think time). Then OCR extraction is sent
1, 2 and 4 at a time (3 sheets each, needs the OCR service and
`e2e/ocr-accuracy/out/sheets/06-general.jpg`). The accounts and the uploaded
photos are deleted at the end.

Options: `E2E_LOAD_USERS=10,50`, `E2E_LOAD_DURATION=30`,
`E2E_OCR_USERS=1,2`, `E2E_PHP_WORKERS=8`.

The `.jmx` plans are generated by `node e2e/jmeter/build-plan.mjs`; open them
in the JMeter GUI (`$JMETER_HOME/bin/jmeter`) to inspect.

## Results

In `e2e/selenium/artifacts/jmeter/`:

- `summary.csv` / `summary.json`: per operation and user level — samples,
  mean, median, 90th/95th/99th percentile, max (ms), error %, requests/s
- `dashboard-100users/index.html`: JMeter's HTML report for the top level
- `*.jtl`: raw samples

These are numbers for this laptop running PHP's built-in server; the
production server (Render + TiDB) has different hardware and network latency.
